2. DOCKER FILES
--------------------------------------------------------------------------------
2.1 teampulse/docker-compose.yml  (development)
  What it starts:
    postgres  - PostgreSQL 16, port 5432, volume for data
    redis     - Redis 7, port 6379
    backend   - built from backend/Dockerfile (dev), port 8000, hot reload
    ai-service- built from ai-service/Dockerfile, port 8001
    frontend  - built from frontend/Dockerfile, port 3000
  How to run:
    cd teampulse
    docker compose up --build
  Notes:
    - The backend reads DATABASE_URL / REDIS_URL from the environment block in
      this file, pointing at the compose service names (postgres, redis), not
      at localhost.
    - Source folders are bind-mounted so code changes reload without a rebuild.
    - Stop with Ctrl+C, or docker compose down. Add -v to delete the database
      volume (destructive).

2.2 teampulse/docker-compose.prod.yml  (self-hosting)
  Same services, production Dockerfiles, no bind mounts, no reload flags,
  restart policies enabled, and secrets expected from the host environment
  rather than hardcoded.
  How to run:
    docker compose -f docker-compose.prod.yml up -d --build
  This is the file to use on a VPS (DigitalOcean, Hetzner, EC2). It is NOT used
  by Vercel or Render, because each of those builds its own service.

2.3 teampulse/docker-compose.test.yml  (testing)
  Spins up the database and Redis only, on non-default ports, so integration
  tests can run without touching your dev data.
  How to run:
    docker compose -f docker-compose.test.yml up -d
  Note: the backend test folders are currently empty, so this file is prepared
  but not exercised by any test suite.

2.4 backend/Dockerfile.prod
  Multi-stage Python image.
  Stage 1 installs build tools and requirements into a virtualenv.
  Stage 2 copies the venv and the app into a slim runtime image.
  Runs as a non-root user, exposes the API port, and starts uvicorn with the
  host 0.0.0.0 so the container is reachable from outside.
  Also runs the Alembic upgrade step at start (check the CMD if you change it).

2.5 ai-service/Dockerfile.prod
  Same pattern for the AI microservice. Smaller because it has fewer
  dependencies. Exposes the AI port and starts uvicorn.

2.6 frontend/Dockerfile.prod
  Three stages: deps -> build -> runner.
  Uses Next.js standalone output, so the final image ships only the server
  bundle instead of the whole node_modules tree.
  Reads NEXT_PUBLIC_* values at build time. Consequence: if you change a
  NEXT_PUBLIC_ variable, you must rebuild the image, not just restart it.

3. DEPENDENCY FILES (what the build step installs)
--------------------------------------------------------------------------------
3.1 backend/requirements.txt
  FastAPI, uvicorn, SQLAlchemy 2.x, asyncpg, alembic, pydantic v2,
  pydantic-settings, python-jose or PyJWT, passlib/bcrypt, httpx, redis,
  python-multipart, email-validator.
  Render: Build Command = pip install -r requirements.txt

3.2 ai-service/requirements.txt
  FastAPI, uvicorn, httpx, pydantic, python-dotenv, groq (or calls Groq over
  plain httpx).

3.3 frontend/package.json
  next, react, react-dom, typescript, tailwindcss, @tanstack/react-query, axios,
  zustand, next-auth, @dnd-kit/*, lucide-react, sonner, class-variance-authority,
  clsx, tailwind-merge, date-fns.
  Scripts: dev, build, start, lint, test (vitest), test:e2e (playwright).
  Note: socket.io-client is listed but the app uses the browser's native
  WebSocket, so it is an unused dependency.

3.4 frontend/package-lock.json
  Locked dependency tree. Commit it. Vercel uses npm ci semantics when a lock
  file is present, which makes builds reproducible.

4. BUILD / RUNTIME CONFIG
--------------------------------------------------------------------------------
4.1 frontend/next.config.js
  Controls image domains, ESLint behaviour during builds, and the security
  headers (CSP, X-Frame-Options, Referrer-Policy, etc.) that the project sets
  in headers().
  Deploy impact: a too-strict CSP will silently block the API or the WebSocket
  in production. If the deployed site loads but cannot talk to the API, check
  connect-src here.

4.2 frontend/tsconfig.json
  TypeScript settings and the "@/*" path alias. A type error fails the Vercel
  build, so this file is effectively part of the deploy gate.

4.3 frontend/tailwind.config.ts and postcss.config.js
  Styling pipeline. Content globs must include ./src/**/*.{ts,tsx}, otherwise
  Tailwind purges the classes and the deployed UI looks unstyled while local dev
  looks fine.

4.4 backend/alembic.ini + backend/alembic/env.py + backend/alembic/versions/
  Migration system. In production you must run:
    alembic upgrade head
  at least once against the cloud database. Render does not do this for you
  unless it is in the start command or the Dockerfile CMD.

4.5 backend/scripts/seed.py
  Inserts demo users, team "Acme Corp", projects WEB/MOB/API and 26 tasks.
  Run once after migrations. Do not run it repeatedly without checking: the
  script creates rows, so duplicates are possible depending on its guards.

4.6 backend/start.sh and ai-service/start.sh
  Container entry scripts. They exist so local Docker and a VPS can start the
  app the same way. On Render, a native Python service ignores these and uses
  the Start Command you type in the dashboard.

4.7 teampulse/frontend/vercel.json - NOT FOUND - please fill in
  The repo does not contain one. Vercel works fine without it because Next.js
  is auto-detected. Add one only if you need custom rewrites, headers, or a
  region pin.

4.8 teampulse/.github/workflows/ - EMPTY
  No CI. Nothing runs tests or lint on push. If you add a workflow, name it
  ci.yml and keep it to install + lint + test so it stays under free minutes.

5. ENVIRONMENT VARIABLES - NAMES ONLY
--------------------------------------------------------------------------------
5.1 Backend (set on Render, or in backend/.env locally)
  ENVIRONMENT                    development | production
  DEBUG                          true | false
  SECRET_KEY                     signs JWTs
  ALGORITHM                      usually HS256
  ACCESS_TOKEN_EXPIRE_MINUTES    default 15
  REFRESH_TOKEN_EXPIRE_DAYS      default 7
  DATABASE_URL                   postgresql+asyncpg://...
  REDIS_URL                      redis:// or rediss://...
  AI_SERVICE_URL                 base URL of the AI microservice
  CORS_ORIGINS                   comma-separated allowed origins
  FRONTEND_URL                   used in links / redirects
  GOOGLE_CLIENT_ID               OAuth (optional)
  GOOGLE_CLIENT_SECRET           OAuth (optional)
  GITHUB_CLIENT_ID               OAuth (optional)
  GITHUB_CLIENT_SECRET           OAuth (optional)
  RATE_LIMIT_PER_MINUTE          if present in settings

5.2 AI service (set on Render, or ai-service/.env locally)
  GROQ_API_KEY                   gsk_... (optional, fallback works)
  GROQ_MODEL                     model name, e.g. llama-3.3-70b-versatile
  ALLOWED_ORIGINS                CORS origins for the AI service
  PORT                           container port
  REQUEST_TIMEOUT_SECONDS        outbound call timeout

5.3 Frontend (set on Vercel, or frontend/.env.local locally)
  NEXT_PUBLIC_API_URL            https://host/api/v1
  NEXT_PUBLIC_WS_URL             wss://host/api/v1
  NEXT_PUBLIC_APP_URL            public site URL
  NEXTAUTH_URL                   must equal the deployed site URL
  NEXTAUTH_SECRET                random string, required in production
  GOOGLE_CLIENT_ID               optional
  GOOGLE_CLIENT_SECRET           optional
  GITHUB_CLIENT_ID               optional
  GITHUB_CLIENT_SECRET           optional

5.4 Rules that prevent most deploy bugs
  - NEXT_PUBLIC_* values are compiled into the bundle. Change = redeploy.
  - SECRET_KEY must be identical across backend restarts; a new key invalidates
    every issued token.
  - NEXTAUTH_SECRET must be stable for the same reason.
  - CORS_ORIGINS and NEXTAUTH_URL must match the real deployed domain, exactly,
    including https and without a trailing slash.
  - .env files are gitignored. Only .env.example files are committed.

6. WHAT EACH PLATFORM ACTUALLY READS
--------------------------------------------------------------------------------
Vercel
  Reads : frontend/package.json, package-lock.json, next.config.js,
          tsconfig.json, tailwind.config.ts, postcss.config.js
  Ignores: Dockerfiles, docker-compose files, backend and ai-service folders
  Because Root Directory = frontend.

Render (backend)
  Reads : backend/requirements.txt (native) OR backend/Dockerfile.prod (Docker)
  Start : uvicorn app.main:app --host 0.0.0.0 --port $PORT
  Ignores: frontend, ai-service

Render (AI service)
  Reads : ai-service/requirements.txt OR ai-service/Dockerfile.prod
  Start : uvicorn main:app --host 0.0.0.0 --port $PORT (adjust to the real
          module name used in that folder)
  Ignores: frontend, backend

Docker host (VPS)
  Reads : docker-compose.prod.yml and the three Dockerfile.prod files
  Needs : a reverse proxy (Caddy/Nginx) for TLS, or Cloudflare in front
